1. Big Data Fundamentals

What is Big Data?

Big Data refers to datasets whose size, speed, or complexity make traditional single-machine tools difficult or inefficient to use. Big Data systems distribute storage and processing across multiple machines.

The 5 Vs

VMeaningExample
VolumeAmount of dataA retailer stores billions of transaction records.
VelocitySpeed at which data arrives and must be processedCard transactions arrive every second.
VarietyDifferent forms of dataTables, JSON events, images, audio, logs.
VeracityData quality, uncertainty, and trustworthinessDuplicate customer profiles or missing values.
ValueUseful outcomes obtained from dataPredicting demand to reduce stock-outs.

Types of data

  • Structured: fixed rows and columns, such as relational database tables.
  • Semi-structured: has tags or keys but flexible structure, such as JSON, XML, and many logs.
  • Unstructured: free-form text, images, audio, video, and documents.

Traditional vs Big Data processing

Traditional approachDistributed Big Data approach
Often scales up one server (vertical scaling).Often scales out by adding machines (horizontal scaling).
May struggle with very high volume or velocity.Partitions data and parallelizes work across a cluster.
Often relational and schema-first.Can combine databases, files, events, and flexible schemas.
Real-world example: A food-delivery platform receives app clicks, restaurant updates, GPS events, payments, and reviews. Data from applications and databases is stored in a data lake; Spark transforms it; dashboards show delivery times and demand.

Main layers

Architecture reminder: HDFS is a distributed storage system, while Spark is a distributed processing engine. They have different responsibilities.

3. Hadoop Ecosystem

Apache Hadoop is an open-source framework and ecosystem for distributed storage and processing. Core components are HDFS, YARN, and MapReduce.

ComponentPurpose
HDFSDistributed file storage with block replication.
YARNCluster resource management and application scheduling.
MapReduceBatch processing model based on map and reduce stages.
Hadoop CommonShared libraries and utilities used by Hadoop modules.

Other tools often found in the wider ecosystem include Hive (SQL-style analytics), HBase (NoSQL wide-column database), Sqoop (historically used for relational data transfer), and Oozie (historical workflow scheduling). Tool availability and current support vary by distribution.

Master/worker idea

In HDFS, the NameNode manages filesystem metadata and DataNodes store blocks. In YARN, the ResourceManager coordinates cluster resources and NodeManagers manage resources on individual worker nodes. These are different responsibilities.

Example: A bank has 20 TB of historical transaction files. HDFS divides files into blocks and distributes replicas across nodes. A batch job can process partitions in parallel rather than reading everything from one computer.

4. HDFS — Hadoop Distributed File System

Key components

  • NameNode: manages filesystem namespace and metadata, including file-to-block mappings and block locations.
  • DataNode: stores actual data blocks and serves read/write requests.
  • Block: a chunk of a file distributed across the cluster. Common configurations historically use 128 MB blocks, but sizes are configurable and depend on the environment.
  • Replication: keeps multiple copies of blocks on different nodes/racks for fault tolerance.

Read flow (simplified)

  1. Client asks the NameNode for file metadata and block locations.
  2. NameNode returns suitable DataNode locations.
  3. Client reads the data directly from DataNodes.
  4. If a DataNode fails, the client can try another available replica.

Write flow (simplified)

  1. Client requests file creation from the NameNode.
  2. NameNode checks permissions and chooses a DataNode pipeline.
  3. Client streams data to the first DataNode, which forwards it to the next replicas.
  4. Acknowledgements flow back; metadata is updated.
Important: The NameNode manages metadata; it does not ordinarily receive every file byte and store the file content itself. DataNodes store the blocks. HDFS is optimized for large files and high-throughput access, not lots of tiny files or low-latency random updates.

Why doesn't DataNode data update the NameNode's file contents?

Because the NameNode is the metadata manager, not the content store. DataNodes send heartbeats and block reports so the NameNode can track node health and which blocks exist. Actual file content remains on DataNodes.

HDFS command examples

hdfs dfs -ls /
hdfs dfs -mkdir -p /demo
hdfs dfs -put localfile.csv /demo/
hdfs dfs -get /demo/localfile.csv .
hdfs dfs -cat /demo/localfile.csv
hdfs dfs -du -h /demo
hdfs dfs -rm /demo/localfile.csv

5. MapReduce and YARN

MapReduce steps

  1. Input splitting: divides input into logical chunks.
  2. Map: transforms each record into intermediate key-value pairs.
  3. Shuffle and sort: groups intermediate values by key across the cluster.
  4. Reduce: aggregates or combines values for each key.
  5. Output: writes results to storage.

Word-count example

Input: cat dog cat

  • Map output: (cat,1), (dog,1), (cat,1)
  • Shuffle/group: cat → [1,1], dog → [1]
  • Reduce output: (cat,2), (dog,1)

YARN components

  • ResourceManager: global cluster resource and scheduling authority.
  • NodeManager: runs on each worker node and manages containers and local resources.
  • ApplicationMaster: coordinates a particular application and requests resources.
  • Container: a bundle of allocated resources, such as memory and CPU, for application work.
Why use YARN? It lets multiple processing frameworks share a cluster and helps allocate resources instead of every application independently controlling the entire cluster.

6. Apache Spark and PySpark

Apache Spark is a distributed processing engine for batch analytics, SQL, streaming workloads, and machine learning. PySpark is its Python API.

Important concepts

  • SparkSession: main entry point for DataFrame and SQL operations.
  • Driver: runs the main application and coordinates execution.
  • Executors: execute tasks and may cache data.
  • Cluster manager: allocates resources (for example, Standalone, YARN, or Kubernetes).
  • Partition: subset of distributed data processed in parallel.
  • Transformation: defines a new dataset, such as filter, select, or map.
  • Action: triggers computation or returns/writes results, such as count, collect, or write.

Lazy evaluation

Spark usually builds a logical execution plan for transformations and executes it when an action is called. This allows Spark to optimize the plan.

RDD vs DataFrame

RDDDataFrame
Distributed collection of objects; lower-level API.Distributed data with named columns and schema.
More manual control, but less SQL optimization.Usually preferred for structured data due to Catalyst and execution optimizations.
Useful for lower-level transformations or legacy examples.Useful for joins, aggregation, filtering, and SQL analytics.

PySpark starter example

from pyspark.sql import SparkSession
from pyspark.sql.functions import col

spark = SparkSession.builder.appName("SalesAnalysis").getOrCreate()

data = [
    (1, "Asha", 1200),
    (2, "Ravi", 800),
    (3, "Meena", 1500)
]
df = spark.createDataFrame(data, ["order_id", "customer", "amount"])

df.show()
df.filter(col("amount") > 1000).show()
df.groupBy().sum("amount").show()

rdd = sc.textFile("input.txt")

counts.takeOrdered(10, key=lambda x: -x[1])

Common Spark terms

  • Shuffle: redistributes data across partitions, often for joins and aggregations; can be expensive.
  • Broadcast variable: sends a read-only value efficiently to executors.
  • Broadcast join: sends a small table to executors to avoid shuffling the large table when appropriate.
  • VectorAssembler: combines feature columns into a single vector column for Spark ML.
  • Checkpointing: saves intermediate state/data to reliable storage to truncate long lineage or support recovery.
  • local[*]: in local mode, asks Spark to use available logical CPU cores on the current machine; it does not create a multi-machine cluster.

7. RDD Programming in PySpark

RDD (Resilient Distributed Dataset) is Spark's fundamental low-level distributed data abstraction. It is an immutable collection of records distributed across partitions and processed in parallel across a cluster.

Why do we use RDD?

  • Resilient: Spark can recompute lost partitions using lineage information.
  • Distributed: data is split into partitions across available workers.
  • Immutable: transformations create a new RDD instead of changing the existing RDD.
  • Parallel processing: operations can run on multiple partitions at the same time.
Real-time example: A company has millions of website log records. Spark can distribute the records across partitions, extract words or URLs, count visits, and calculate the most visited pages.

Creating an RDD

from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("RDD_Demo").getOrCreate()
sc = spark.sparkContext

numbers = [10, 20, 30, 40, 50]
rdd = sc.parallelize(numbers)

print(rdd.collect())

Ways to create an RDD

# 1. From a Python collection
rdd1 = sc.parallelize([1, 2, 3, 4, 5])

# 2. From a text file
rdd2 = sc.textFile("data/input.txt")

# 3. From an existing DataFrame
rdd3 = df.rdd

RDD transformations

Transformations are lazy operations that create a new RDD. They are not executed immediately.

TransformationPurposeExample
map()Apply a function to every element.rdd.map(lambda x: x * 2)
filter()Keep elements that satisfy a condition.rdd.filter(lambda x: x > 20)
flatMap()Apply a function and flatten the returned collections.lines.flatMap(lambda x: x.split())
distinct()Return unique elements.rdd.distinct()
union()Combine two RDDs.rdd1.union(rdd2)
sortBy()Sort elements using a key function.rdd.sortBy(lambda x: x)

RDD actions

Actions trigger execution and return a result to the driver or write data to external storage.

ActionPurposeExample
collect()Return all elements to the driver.rdd.collect()
count()Count elements.rdd.count()
first()Return the first element.rdd.first()
take(n)Return the first n elements.rdd.take(3)
reduce()Combine elements using a function.rdd.reduce(lambda a,b: a+b)
saveAsTextFile()Write RDD data to a directory.rdd.saveAsTextFile("output")
Important: Avoid using collect() on a very large RDD because all records are transferred to the driver and may cause memory errors. Use take() or distributed output operations when appropriate.

Word count using RDD

lines = sc.parallelize([
    "big data with spark",
    "spark is distributed",
    "big data processing"
])

words = lines.flatMap(lambda line: line.lower().split())
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)

for word, count in counts.collect():
    print(word, count)

Pair RDD operations

A pair RDD stores key-value pairs. It is useful for grouping and aggregation tasks.

sales = sc.parallelize([
    ("Bangalore", 1000),
    ("Chennai", 1500),
    ("Bangalore", 2000),
    ("Chennai", 500)
])

totals = sales.reduceByKey(lambda a, b: a + b)
print(totals.collect())

# Example output:
# [('Bangalore', 3000), ('Chennai', 2000)]

8. Machine Learning with PySpark MLlib

MLlib is Apache Spark's machine learning library. It provides scalable algorithms and tools to prepare data, build pipelines, train models, and evaluate predictions on distributed datasets.

Why use machine learning with PySpark?

  • Process large datasets distributed across a Spark cluster.
  • Prepare and transform features using Spark ML transformers.
  • Train machine learning models using Spark ML estimators.
  • Build repeatable workflows using ML Pipelines.
  • Evaluate models using suitable metrics.
Real-time example: An online shopping company wants to predict whether a customer will purchase a product. Customer age, browsing time, previous purchases, and cart value can be used as features. PySpark can prepare the data, train a classification model, and predict purchase likelihood.

Step 1: Read a dataset

from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("SparkML").getOrCreate()

data = spark.read.csv(
    "data/heart.csv",
    header=True,
    inferSchema=True
)

data.printSchema()
data.show(5)

Step 2: Prepare features using VectorAssembler

Most Spark ML algorithms expect input features in a single vector column, commonly named features. VectorAssembler combines selected numeric columns into that vector.

from pyspark.ml.feature import VectorAssembler

feature_cols = [
    "age",
    "cholesterol",
    "blood_pressure"
]

assembler = VectorAssembler(
    inputCols=feature_cols,
    outputCol="features"
)

assembled_data = assembler.transform(data)
assembled_data.select("features", "target").show(5, truncate=False)
Remember: Do not include the target/label column in inputCols. Handle nulls and categorical columns before assembling features; categorical values may need StringIndexer and OneHotEncoder.

Step 3: Split data into training and testing sets

train_data, test_data = assembled_data.randomSplit(
    [0.8, 0.2],
    seed=42
)

print("Training rows:", train_data.count())
print("Testing rows:", test_data.count())

Step 4: Train a Logistic Regression model

from pyspark.ml.classification import LogisticRegression

lr = LogisticRegression(
    featuresCol="features",
    labelCol="target"
)

lr_model = lr.fit(train_data)

Step 5: Generate predictions

predictions = lr_model.transform(test_data)

predictions.select(
    "target",
    "prediction",
    "probability"
).show(10, truncate=False)

Step 6: Evaluate the model

from pyspark.ml.evaluation import (
    BinaryClassificationEvaluator,
    MulticlassClassificationEvaluator
)

accuracy_evaluator = MulticlassClassificationEvaluator(
    labelCol="target",
    predictionCol="prediction",
    metricName="accuracy"
)

accuracy = accuracy_evaluator.evaluate(predictions)
print("Accuracy:", accuracy)

auc_evaluator = BinaryClassificationEvaluator(
    labelCol="target",
    rawPredictionCol="rawPrediction",
    metricName="areaUnderROC"
)

auc = auc_evaluator.evaluate(predictions)
print("AUC:", auc)

ML Pipeline concept

A Pipeline connects multiple stages, such as indexing categorical columns, assembling features, and fitting a model. It helps apply the same processing steps consistently during training and prediction.

from pyspark.ml import Pipeline
from pyspark.ml.feature import VectorAssembler
from pyspark.ml.classification import RandomForestClassifier

assembler = VectorAssembler(
    inputCols=["age", "cholesterol", "blood_pressure"],
    outputCol="features"
)

rf = RandomForestClassifier(
    featuresCol="features",
    labelCol="target",
    numTrees=50
)

pipeline = Pipeline(stages=[assembler, rf])
pipeline_model = pipeline.fit(train_data)
pipeline_predictions = pipeline_model.transform(test_data)
Dataset note: The sample code assumes the dataset has the listed columns, numeric feature values, a numeric label column, and no unresolved null values. Change column names and preprocessing to match your actual dataset. Model accuracy depends on data quality, features, algorithm, and evaluation method; it cannot be guaranteed in advance.

  • Columnar layout lets engines read only needed columns.

  • It supports nested data and is used by many analytics engines.

10. ETL/ELT and Big Data Pipelines

  • Extract: obtain data from databases, files, APIs, or event streams.
  • Transform: clean types, remove duplicates, standardize values, join datasets, and derive metrics.
  • Load: write processed data to a target system.

ETL transforms before loading into the target. ELT loads raw data first and transforms within the destination platform. Both patterns are useful in different architectures.

Example daily sales pipeline

  1. Extract orders and payment records from operational databases and files.
  2. Validate required fields and deduplicate using a stable event/order ID.
  3. Standardize timestamps and currencies.
  4. Join orders with customer/product dimensions.
  5. Write curated Parquet/table data partitioned by date.
  6. Update dashboard tables and alert if data is late or quality checks fail.

Pipeline design principles

  • Idempotency: rerunning the same input should not create duplicate effects.
  • Retries: retry temporary failures with limits and backoff.
  • Checkpointing: save progress or intermediate results so processing can resume.
  • Schema evolution: handle added/changed fields safely.
  • Observability: monitor freshness, throughput, failures, lag, and data quality.
  • Orchestration: schedule dependencies and retries with a workflow tool.

11. Data Quality, Security, and Governance

Data quality dimensions

  • Completeness: required values are present.
  • Accuracy: values represent reality correctly.
  • Consistency: systems agree on definitions and values.
  • Validity: values follow allowed formats/ranges.
  • Uniqueness: duplicate records are controlled.
  • Timeliness: data arrives when needed.

Security and governance practices

  • Least-privilege access and role-based permissions.
  • Encryption in transit and at rest where supported and required.
  • Protect credentials in secrets managers/environment configuration, not in source code.
  • Mask or minimize personal data; follow applicable policies and laws.
  • Maintain metadata, data lineage, ownership, retention rules, and audit logs.
  • Validate input and restrict network exposure.

Reliability and scaling

Distributed systems use partitioning, replication, retries, and monitoring to handle large workloads and failures. Replication improves availability but does not replace backups, governance, or recovery testing.

Common misunderstandings

  • HDFS NameNode stores metadata; DataNodes store file blocks.
  • YARN manages cluster resources; HDFS manages distributed file storage.
  • Map and Reduce are processing stages; shuffle and sort groups intermediate keys.
  • Spark transformations are usually lazy; actions trigger execution.
  • RDDs are lower-level distributed collections; DataFrames have named columns and a schema.
  • More partitions can enable more parallelism but also add overhead.
  • VectorAssembler combines multiple input columns into one feature vector for Spark ML.
  • Parquet is a file format; HDFS is storage; Spark is a processing engine.
